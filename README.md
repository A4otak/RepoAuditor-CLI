# RepoAuditor CLI

Консольная утилита для **глубокого статического аудита** локальных проектов и GitHub-репозиториев перед публикацией на форумах. Проверяемый код **никогда не запускается и не импортируется** — только разбор через `ast` и поиск по регулярным выражениям.

Кроссплатформенно: Windows, Linux, macOS. Требуется Python 3.11+.

## Быстрый старт

**Windows:** дважды щёлкните `start.bat`.
**Linux / macOS:** `./start.sh` (при необходимости `chmod +x start.sh`).

Скрипты сами создают `.venv`, ставят зависимости и запускают программу. Вручную:

```bash
pip install -r requirements.txt
python main.py
```

## Меню

| Пункт | Что делает |
|---|---|
| `[1]` | Быстрый аудит локальной папки: код, безопасность, зависимости |
| `[2]` | Проверка GitHub-репозитория по ссылке. Ссылка очищается автоматически: пробелы, кавычки, скобки (`[url]`), `.git` и `/tree/...` отбрасываются |
| `[3]` | Полный аудит + ИИ. Черновик поста необязателен: Enter — пропустить, тогда ИИ анализирует только репозиторий |
| `[4]` | Настройки ИИ: URL сервера, модель, API-ключ |
| `[0]` | Выход |

`Ctrl+C` в любой момент завершает работу без трейсбека (временные файлы удаляются).

## Что проверяется

**Безопасность** (`core/security_scanner.py`)
- Запрещённые файлы: `.exe`, `.dll`, `.so`, `.dylib`, `.msi`, `.scr`, `.jar`, `.apk`.
- Разбор всех `.py` через `ast`: синтаксические ошибки (файл и строка); `eval`, `exec`, `compile`, `__import__`, `os.system`, `subprocess` с `shell=True`, `winreg`, `ctypes`, `pickle.loads`, `marshal`.
- Признаки обфускации: base64/zlib-декодирование вместе с `eval/exec`, строки длиннее 500 символов без пробелов.
- Все внешние URL и IPv4 (известные домены вроде `github.com`/`pypi.org` и тестовые IP-заглушки `1.2.3.4`, `127.0.0.1`, `0.0.0.0`, `8.8.8.8`, `1.1.1.1` отделены от сторонних).
- Захардкоженные секреты: `api.telegram.org/bot`, `discord.com/api/webhooks`, `sk-…`, `ghp_…` и др. В отчёте значения маскируются.

**Качество** (`core/quality_checker.py`)
- Сверка сторонних импортов с `requirements.txt` (стандартная библиотека и локальные модули исключаются) — ловит будущий `ModuleNotFoundError` на чистом ПК.
- Наличие `README.md`; забытые папки `.venv`, `results`, `__pycache__`.
- `.bat`: кириллица/не-ASCII и окончания `CRLF`. `.sh`: окончания `LF`.

**ИИ-аудит** (`core/llm_auditor.py`, по желанию):
- с черновиком поста — четыре раздела: *Что это*, *Безопасно ли*, *Запускается ли и делает ли обещанное*, *К чему может придраться модерация*;
- без черновика — три блока с чётким вердиктом в каждом: *Что это*, *Безопасно ли запускать*, *Запускается ли и какие есть нюансы/ограничения*.

## Итоговый статус

- `ГОТОВ К ПУБЛИКАЦИИ` (зелёный) — нет находок уровней КРИТИЧЕСКАЯ, ВЫСОКАЯ и СРЕДНЯЯ;
- `ЕСТЬ ЗАМЕЧАНИЯ` — есть находки уровня ВЫСОКАЯ или СРЕДНЯЯ, нужна проверка вручную;
- `КРИТИЧЕСКИЕ ОШИБКИ` — бинарники, синтаксические ошибки, забытые зависимости, секреты, обфускация.

Находки уровней НИЗКАЯ и ИНФО показываются в таблицах как подсказки и на статус не влияют.

Полный отчёт сохраняется в `reports/audit_YYYY-MM-DD_HH-MM-SS.md`. Если в режиме `[3]` получен ответ ИИ, он попадает в отчёт отдельным разделом `## Вердикт ИИ-аудитора`.

## Настройка ИИ

По умолчанию — локальная Ollama: `http://localhost:11434/v1/chat/completions`. Также поддерживаются LM Studio (`http://localhost:1234/v1/chat/completions`) и любой OpenAI-совместимый облачный API (Groq, Google AI Studio и др.). Параметры хранятся в `config.json` (исключён из git); ключ можно задать и переменной окружения `REPOAUDITOR_API_KEY`.

Меню `[4]` — подменю с действиями: выбор сервера, `[m]` модель, `[k]` API-ключ, `[l]` загрузка списка моделей, `[c]` лимит контекста, `[t]` проверка подключения, `[r]` сброс настроек. Каждое изменение сохраняется сразу.

- `[l]` делает `GET {URL без /chat/completions}/models` с заголовком `Authorization: Bearer <ключ>`, печатает нумерованный список и сохраняет выбранную по номеру модель в `config.json`. Префикс `models/` (Google AI Studio) в именах обрезается. Модели не для анализа кода (в ID есть `whisper`, `tts`, `orpheus`, `embedding`, `image`, `lyria`, `guard`, `transcribe`) скрываются; если скрылось бы всё — показывается исходный список.
- `[c]` задаёт лимит кода проекта в запросе (число от 1 000 до 1 000 000 или `auto`). В таблице настроек значение показано как `авто (10 000 / 24 000)` или заданное число.
- `[r]` (с подтверждением) возвращает URL, модель и лимит к значениям по умолчанию и стирает API-ключ из `config.json`. Ключ из переменной окружения `REPOAUDITOR_API_KEY` не затрагивается.
- `[t]` отправляет «Ответь одним словом: ОК» на сохранённый URL; в ответ — зелёный ответ модели либо точный код HTTP/сетевая ошибка.
- API-ключ вводится **видимо** (чтобы убедиться, что вставка сработала); в таблице настроек он маскируется как `gsk_...9a2f`.
- Ввод URL автоматически очищается от пробелов, кавычек и скобок (`[https://…]`).
- Сетевой клиент использует принудительный IPv4 и системный прокси/VPN (`trust_env`), что решает зависания на Windows. Таймауты задаются на одну попытку: тест `[t]` и список моделей `[l]` — 15 с (1 повтор при 503/429); полный аудит на облачных API — 40 с (2 повтора); на локальных серверах — 300 с (3 повтора). Сам по себе таймаут не повторяется — повторы только при 503/429.
- **Ctrl+C во время запроса к ИИ** (тест, список моделей, полный аудит) отменяет только запрос: появляется «Запрос к ИИ отменён пользователем», а программа остаётся в работе — возвращается в меню настроек либо завершает отчёт без блока ИИ. Подсказка `(Ctrl+C — отменить)` показывается рядом со спиннером.

**Лимиты и повторы (бесплатные облачные API):**
- Размер запроса задаётся параметром `max_context_chars` в `config.json` (`null` — авторежим). Авторежим: локальный сервер (Ollama / LM Studio, localhost, адреса локальной сети) — до 24 000 символов кода; облачный API — до 10 000, а README, черновик, дерево файлов и списки находок тоже сокращены. Если лимит задан вручную (например, 50000 для платного API), он применяется к коду, а README, дерево файлов, черновик и списки увеличиваются пропорционально.
- HTTP 413 (запрос слишком велик) — страховка работает и при ручном лимите: выводится «Запрос превысил лимит токенов сервера, сжимаю контекст и повторяю...», все части запроса урезаются вдвое (код 10 000 → 5 000 символов) и запрос повторяется; максимум 2 сжатия.
- HTTP 503 / 429 (временная перегрузка): повторы с паузой 4 секунды (тест и список моделей — 1, облачный аудит — 2, локальный — 3), в консоль выводится статус ожидания.

Если сервер не запущен или ключ не задан, программа сообщит об этом, а остальные проверки выполнит как обычно.

**Приватность:** при нелокальном URL перед отправкой запрашивается подтверждение — код проекта и черновик поста уйдут на внешний сервер. Содержимое проекта передаётся модели как данные, а не как инструкции.

## Ограничения

Статический анализ не заменяет ручную проверку: возможны ложные срабатывания и пропуски (например, сильно обфусцированный код). Сверка зависимостей учитывает типичные несовпадения имён (`PIL` → `pillow`), но не все.

## Структура

```
main.py                  меню и сценарии
core/fetcher.py          локальная папка / ZIP с GitHub (aiohttp)
core/security_scanner.py безопасность
core/quality_checker.py  зависимости, README, скрипты запуска
core/llm_auditor.py      ИИ-аудит
core/models.py           общие модели данных
utils/report.py          таблицы rich и Markdown-отчёт
utils/io_helper.py       выбор папки, ввод черновика
start.bat / start.sh     запуск
```
